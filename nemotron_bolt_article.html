Thank you, NVIDIA! 💚 For years, running a true 70-billion parameter model on an entry-level consumer GPU felt like science fiction. If you owned a sub-$400 card (like an RTX 5060 Ti 16GB), you were practically barred from running frontier-tier open models locally. NVIDIA changed the game with the open release of the 24GB Nemotron 3.5 Bolt (74B Total / 9B Active). By pairing linear Mamba-2 State Space Model (SSM) layers with a massive 496-expert LatentMoE router, NVIDIA created an architectural masterpiece that makes massive model inference possible on consumer silicon. Naturally, we put this to the test on this exact machine—and engineered a bare-metal CUDA execution pipeline that unlocks full performance. Here is what we discovered, how it compares to llama.cpp, and why architectural pipelining makes all the difference. ━━━━━━━━━━━━━━━━━━━━━ 💥 The Benchmark Showdown Hardware: NVIDIA GeForce RTX 5060 Ti 16GB + 32GB DDR5 RAM Model: NVIDIA-Nemotron-3.5-Bolt-74B-A9B-24GB (40 MoE Layers, 19,840 Total Experts) Prompt: "Explain the difference between SSD and RAM in simple terms." ━━━━━━━━━━━━━━━━━━━━━ 1️⃣ llama.cpp Full Offload (-ngl 88): Result: < 1.0 tok/s. WDDM 3.x shared memory paging causes constant PCIe thrashing. The GPU stalled, dropping to 9% utilization at 20 Watts. 2️⃣ llama.cpp New MoE Cache (--moe-cache-mib 6000): Result: 1.7 tok/s prefill | 3.5 tok/s decode. Why did it stall? Nemotron Bolt features 496 experts per layer = 19,840 total experts. A 6GB cache holds only ~22% of them. On every single miss, llama.cpp halts execution (cudaStreamWaitEvent), causing up to 48 sequential waits per token! 3️⃣ llama.cpp Partial CPU Fallback (-ngl 48): Result: 5.6 tok/s prefill | 6.9 tok/s decode. Faster than the cache, but maxes out 100% of all CPU cores via AVX-512/AVX2 on system memory. 4️⃣ MinnieTheMoEcher (Our Bare-Metal CUDA Engine): Result: 21.54 tok/s prefill | 13.51 tok/s decode | 0% CPU Load! 📊 The Scorecard: • Decode Speed: 13.51 tok/s vs 3.50 tok/s (3.86× faster than llama.cpp's MoE cache) • Prefill Speed: 21.54 tok/s vs 1.70 tok/s (12.6× faster) • Hardware Efficiency: 100% GPU Tensor Cores, zero CPU core burn. ━━━━━━━━━━━━━━━━━━━━━ 🔍 Why Minnie Goes 3.86× Faster ━━━━━━━━━━━━━━━━━━━━━ The bottleneck on consumer cards with fine-grained MoEs isn't raw compute—it is PCIe serialization stalls. Minnie achieves 13.5 tok/s through two core architectural innovations: ✅ Asynchronous Double-Buffered DMA: While Layer N is executing Mamba-2 SSM and Attention on the Tensor Cores, Layer N+1's required experts are pre-streamed in parallel over dedicated copy streams. The PCIe transfer latency is completely masked behind computation. ✅ Pinned Host DRAM L2 Tier: Weights reside in non-pageable physical RAM via VirtualAlloc, completely eliminating Windows WDDM driver paging faults. ━━━━━━━━━━━━━━━━━━━━━ 🍏 The Next Frontier: Apple Silicon Metal Port ━━━━━━━━━━━━━━━━━━━━━ So what's next on our roadmap? We are already bringing Nemotron 3.5 Bolt to Apple Silicon (macOS) with native Apple Metal 3.1+ and our Hardware MPP Tiled Matrix Engine. Because Apple Silicon uses a Unified Memory Architecture (UMA) where CPU and GPU share the same physical memory pool (up to 128GB+ on M-Series Max and Ultra): • There is ZERO PCIe bus bottleneck. • MoE expert routing is 100% zero-copy. • On-the-fly SRAM tile dequantization will run seamlessly. Mac users will soon be able to run Nemotron 3.5 Bolt with zero memory transfers whatsoever.
