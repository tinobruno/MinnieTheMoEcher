1. The 552-Billion Parameter Challenge on a Single Workstation

Running DeepSeek-V4.1-Flash (1017 Release) locally on a single-GPU workstation is one of the ultimate stress tests in modern systems engineering. While only 14 billion parameters are activated per token, the total model spans 552 billion parameters across 40 layers and 15,360 routed experts (384 routed experts per layer, top-6 active experts per token + 1 shared expert, expert dimensions 5120 × 2304), paired with Multi-head Latent Attention (MLA) and 4-branch Multi-Hyper-Connections (mHC).

Even when compressed to extreme 2-bit/3-bit quantization (IQ2_XXS for gate/up + Q2_K for down, totaling 9.95 MB / 9.49 MiB per routed expert), the 15,360 routed experts alone weigh 152.9 GB (142.4 GiB)—far exceeding the 96 GB GDDR7 VRAM of an NVIDIA RTX PRO 6000 Blackwell (sm_120a). Every single-GPU inference engine must solve a fundamental physics problem: how to move expert weights across NVMe SSD, System DDR5 RAM, PCIe 5.0, and GPU VRAM without starving the Blackwell Tensor Cores.

Recently, Salvatore Sanfilippo (antirez) released DwarfStar (ds4) with a CUDA SSD-streaming backend (ds4_cuda.cu) for DeepSeek-V4.1-Flash (ds41f-q2). On a 128 GB NVIDIA DGX Spark (GB10), antirez published official benchmarks showing 84.90 tok/s on 2K prefill (93–100 tok/s at 3.2K, 116.34 tok/s at 4K) and 9.30 tok/s on single-session decode (docs/DGX_SPARK.md, QA_BEFORE_RELEASES.md). When we project ds4_cuda.cu's exact memory and I/O pipeline (75.0 GiB / 8,090 cached experts after its 8.0 GiB VRAM reserve, synchronous per-layer pread() across 3 separate GGUF tensors) onto an NVIDIA RTX PRO 6000 96GB + PCIe 5.0 NVMe SSD, its analytical ceiling is ~145–165 tok/s on 2K prefill and ~6.9–8.5 tok/s (~7.8 tok/s midpoint) on autoregressive decode using ~4.8 GB of host RAM.

In MinnieTheMoEcher v2.09, our 3-Tier Hierarchical Memory Architecture (VRAM Hot/Cold L1 + Pinned Host DDR5 L2 + NVMe SSD) pushes empirical measured decode throughput on the RTX PRO 6000 96GB to 14.50 tok/s (1.56× faster than DwarfStar's published 128 GB DGX Spark decode and ~1.86× faster than its RTX PRO 6000 projection).

Then we asked a much tougher engineering question:

"What if we strip away Minnie's 42.9 GB DDR5 RAM advantage? What if we cap Minnie to 4.80 GB of host RAM—or even disable the DRAM expert cache completely (0.30 GB host RAM, pure NVMe SSD streaming)? Can our bare-metal CUDA architecture still beat both DwarfStar's 128 GB DGX Spark baseline and its RTX PRO 6000 projection?"

The answer—verified on bare metal on our RTX PRO 6000 96GB across three controlled benchmark suites—is yes, across both prefill and decode, in every single configuration.

3. Code-Level Deep Dive: Four Architectural Reasons Minnie Beats DwarfStar

Breakthrough #1: Contiguous Expert Packing on Disk (1 NVMe Read vs. 3 Scattered Reads 1.17 GB Apart)

Both engines use the same quantization format for cold routed experts (5120 × 2304): IQ2_XXS for gate (3,186,688 bytes) and up (3,186,688 bytes), plus higher-precision Q2_K for the down projection (4,055,040 bytes), totaling 9,953,280 bytes (9.95 MB / 9.49 MiB) per expert.

However, their on-disk layouts are completely different:

  • DwarfStar (ds4_cuda.cu:29169-29190) streams directly from a standard .gguf file where all 384 experts' gate matrices are stored in blk.L.ffn_gate_exps.weight, followed 1.17 GB later by blk.L.ffn_up_exps.weight, followed 1.17 GB later by blk.L.ffn_down_exps.weight. Every single cold expert miss during batch = 1 decode requires 3 separate non-adjacent pread() syscalls across a 3.8 GB span per layer (130–160 scattered reads per token).
  • MinnieTheMoEcher (moe_experts_iq2.bin) packs gate + up + down for each expert into one single contiguous 9.95 MB block on disk. Every cold expert miss requires just 1 sequential NVMe read, slashing NVMe queue overhead by 3× and maximizing single-expert PCIe 5.0 DMA throughput.

Breakthrough #2: Hardware NVFP4 Hot Tier (4.38 MB) + Dynamic Per-Layer VRAM L1 LRU with 1.8 TB/s D2D Warm-Up

While DwarfStar (ds4_cuda.cu:29068) stores all cached experts in uniform 9.95 MB IQ2_XXS+Q2_K format and hardcodes an 8.00 GiB free-VRAM reserve (kReserveBytes), fitting 8,090 experts in a single global Clock-sweep pool, MinnieTheMoEcher v2.09 uses a Mixed-Precision + Frequency-Ranked Architecture:

  • Native Blackwell NVFP4 Hot Tier (3,840 Experts in 16.8 GB): The top 3,840 highest-frequency routed experts (96 per layer) reside permanently in VRAM in hardware NVFP4 (sm_120a 4-bit Tensor Core format) at ~4.38 MB per expert—2.27× more compact in VRAM than 9.95 MB IQ2_XXS+Q2_K while executing directly on Blackwell mma.sync FP4 Tensor Cores!
  • Per-Layer VRAM Cold L1 Pool (1,100 Experts in 10.2 GB): Partitioned into 8 Pinned Static Slots (320 globally popular cold experts) and 19–20 Dynamic LRU Slots per Layer (780 dynamic slots).
  • Zero-Cost Prefill-to-Decode D2D Warm-Up (1.8 TB/s): At the end of each layer during prefill, the cold experts activated by the prompt are already resident in the GPU's 2.65 GB VRAM scratch buffer. Minnie ranks them by activation frequency and copies the top 12 prompt-specific cold experts per layer directly from VRAM scratch into that layer's VRAM L1 LRU slots via cudaMemcpyDeviceToDeviceAsync (1.8 TB/s)—pre-warming 480 prompt-relevant cold experts in VRAM before decode token #1 is even generated!

Breakthrough #3: Layer-Outer, 4,096-Token Super-Chunk Prefill (202.56 tok/s No-DRAM)

In a traditional chunked prefill engine (for chunk_512 { for layer = 0..39 }), a 2,048-token or 3,072-token prompt is sliced into four to six 512-token chunks. Because each token routes to 6 experts out of 384, a single 512-token chunk activates roughly 250 to 275 unique experts per layer (the coupon-collector effect). If the outer loop iterates over 512-token chunks, Layer L must fetch those same cold experts from the NVMe SSD on Chunk 0, evict them when moving to Layer L+1, and then re-read the exact same cold experts 4 to 6 times per prompt!

We inverted the prefill execution topology into a Layer-Outer, Sub-Chunk-Inner Super-Chunk (up to 4,096 tokens):

[ Prompt Super-Chunk: Up to 4,096 Tokens (Sub-Chunks c = 0..7 of 512 Tokens) ] │ └──► For Layer L = 0 .. 39: ├── Step 1 (All Sub-Chunks): Run Fused mHC Add-Norm + MLA Attention + Router Gate ├── Step 2 (Super-Chunk Union): Deduplicate Cold Experts across all 4,096 tokens │ └── Stream unique Cold Experts from NVMe SSD / DDR5 into 280-slot (2.65 GB) │ VRAM Scratch Buffer ONCE per Layer (16 parallel NVMe I/O threads) ├── Step 3 (All Sub-Chunks): Execute Vectorized sm_120a SwiGLU & Down-Projection │ └── Reads Cold Weights at 1.8 TB/s from VRAM Scratch (0 redundant SSD reads!) └── Step 4 (D2D Warm-Up): Copy Top-12 Prompt-Activated Cold Experts from VRAM Scratch └──► Per-Layer VRAM L1 Cold LRU Cache at 1.8 TB/s (cudaMemcpyDeviceToDeviceAsync)

Breakthrough #4: Compute-Overlapped Decode NVMe I/O vs. Synchronous cudaStreamSynchronize()

In ds4_cuda.cu:29029 (ds_expert_cache_prepare_layer), DwarfStar calls cudaStreamSynchronize(c->stream) at the start of every layer—stalling the GPU while the CPU performs synchronous pread() calls for missing gate, up, and down slices—and then blocks on uploads.finish() before launching MoE compute.

MinnieTheMoEcher v2.09 decouples hits from misses inside every layer: it immediately dispatches all VRAM-resident and DRAM-cached experts onto main_stream_, overlapping Blackwell Tensor Core execution with the parallel contiguous NVMe SSD read of the remaining cold expert.
