Architectural Philosophy: Static-Linked Modularity

MinnieTheMoEcher is engineered for high-throughput bare-metal inference on NVIDIA CUDA (sm_80–sm_120) and Apple Silicon Metal. In ultra-low latency inference, every CPU microsecond and memory transaction directly impacts TTFT and ITL.

Rather than using dynamic runtime plugin systems (such as dlopen / LoadLibrary) or IPC microservices—which destroy performance with indirection and memory copies—we use Pure C++ Static Linking.

❌ Dynamic Loading / IPC Microservices
  • ⚠️ Virtual method tables (vtable) disable compiler loop vectorization
  • ⚠️ Shared pointer dereferences add cache thrashing
  • ⚠️ Wrapper structs force intermediate heap allocations
  • ⚠️ Inter-process communications introduce socket/pipe latency
✅ Minnie's Static-Linked Modularity
  • ✨ Direct Inlining: MSVC/NVCC inlines hot loops across translation units
  • ✨ Pointer Arithmetic: Direct access to pre-allocated VRAM buffers
  • ✨ Zero Allocation: Exactly 0 bytes heap growth during generation
  • ✨ Zero Merge Hell: Clean physical file boundaries for Git branches

The .inl Pattern: Why It Solves Merge Conflicts

Model forward passes are placed in .inl (Inline Implementation) files inside src/models/.

How it Works

Instead of defining separate classes or virtual interfaces, src/engine.hpp includes the implementation directly inside the body of class MoecherEngine:

src/engine.hpp 
class MoecherEngine {
public:
    // Core engine interface
    bool init(const std::string& manifest_path);
    bool forward(int token, int pos, bool is_prefill = false, int draft_idx = 0);

private:
    // Architecture-specific forward passes declared as private members:
    bool forward_qwen(int token, int pos, bool is_prefill, int draft_idx);
    bool forward_deepseek(int token, int pos, bool is_prefill, int draft_idx);

    // Private hardware state (VRAM pointers, CUDA streams, KV caches)
    GPUTensor d_intermediate_;
    cudaStream_t main_stream_;
    cublasHandle_t cublas_handle_;
};

// Direct static inclusion of member function implementations:
#include "models/model_qwen.inl"
#include "models/model_deepseek.inl"

Result: An agent working on Qwen touches only model_qwen.inl. An agent working on DeepSeek touches only model_deepseek.inl. Git merges are mathematically disjoint and cleanly orthogonal.

Step-by-Step: Adding a New Model Architecture

1

Create a dedicated branch

Always branch from the main modular baseline:

terminal 
git checkout -b feature/model-mistral4
2

Implement the forward pass in src/models/model_mistral4.inl

Write your forward pass directly as a member function:

src/models/model_mistral4.inl 
#pragma once

bool MoecherEngine::forward_mistral4(int token, int pos, bool is_prefill, int draft_idx) {
    // 1. Embedding lookup
    // 2. Transformer layer loop (Self-Attention + Granular MoE MLP)
    // 3. Final RMSNorm + LM Head projection
    return true;
}
3

Register in src/engine.hpp

Add the declaration and dispatch switch:

src/engine.hpp 
// In MoecherEngine::forward()
if (cfg_.architecture == "mistral4") {
    return forward_mistral4(token, pos, is_prefill, draft_idx);
}

// At bottom of src/engine.hpp
#include "models/model_mistral4.inl"
4

Compile & Test

terminal 
.\build_fast.bat
.\moecher.exe --manifest models/mistral4/moecher_manifest.json --port 8001

Agentic Tooling & MCP Integration

Server-side tool execution, OpenAI tool calling schema resolution, and MCP client bridges are isolated in src/agentic.hpp and src/agentic.cpp.

Adding a New Built-in Tool

  1. Open src/agentic.cpp and append your tool JSON schema to get_builtin_tools_json().
  2. Add the tool executor function (e.g. execute_custom_analysis()) in src/agentic.cpp.
  3. Hook the execution in execute_tool_call().
  4. Rebuild with .\build_fast.bat.

Zero Decode Bypass (ZDB) & Hybrid Arbiter

ZDB delivers sub-100ms structured decision-making by evaluating target logit boundaries directly during prompt prefill, bypassing the autoregressive decode loop completely (completion_tokens = 0).

Key Subsystem Functions (src/zdb.cpp)

  • slice_candidate_logits() — Slices vocabulary logits corresponding to permitted candidate choices.
  • evaluate_hybrid_arbiter() — Evaluates Top-1 logit margin, candidate confidence threshold, and argmax verification.
  • route_decision_path() — Determines whether to execute System 1 (0-decode fast path) or trigger graceful fallback to System 2 deliberate reasoning.

Tooling Safety & Sandboxing Architecture

MinnieTheMoEcher implements a strict 3-pillar defense-in-depth security model to guarantee enterprise-grade safety for LLM tool calling and MCP integrations:

🛡️ 1. Secure-by-Default Runtime
  • Safe Mode: Server-side host execution (g_server_exec), tooling schemas (g_enable_tools), and write operations (g_allow_file_write) are disabled by default.
  • Pure Inference: Standard OpenAI client-side tool calling is supported out-of-the-box without touching the host OS.
  • Opt-In Gating: Host execution requires explicit --allow-host-exec, which prints a high-visibility terminal security warning banner.
🔒 2. Compile-Time Host Gating
  • Physically Inert: Default release builds compile with -DENABLE_UNSAFE_HOST_EXEC=OFF.
  • Zero Shell Access: execute_system_command() physically cannot run arbitrary host shell commands unless explicitly enabled at build time via -DENABLE_UNSAFE_HOST_EXEC=ON.

📁 3. Strict Workspace Path Sandboxing

All built-in file operations (read_file, write_file, edit_file) are strictly confined within --workspace <path> (default: ./workspace):

  • Path Traversal Protection: Any attempt to escape via ../ or parent directory climbing is rejected.
  • Drive Root Isolation: Absolute paths to root directories (e.g. C:\Windows, /etc/) are intercepted.
  • Sensitive Credential Blocking: Access to sensitive credential patterns (.env, .git, .ssh, id_rsa, cookie_jar.json, authorized_keys) is permanently blocked.
  • Write Access Gating: File creation and modification are rejected unless launched with --allow-file-write.
